## Intent

**Problem:** The tracer page from ticket 1 runs only in a browser. Capacitor iOS and Android projects are needed so it can be installed and opened as an app on the reference phones (Galaxy A35-class, iPhone 13). That gates the renderer bake-off (tickets 8 and 9).

**Approach:** Add Capacitor 8.5.x to `apps/client` with a `capacitor.config.ts` (webDir `dist`, appId `app.numception.dev`, appName `Numception`). Generate the `ios/` and `android/` projects under `apps/client` with the Capacitor CLI. Add a `cap:sync` script that builds the client at base `/` and syncs both platforms. Only `apps/client` imports `@capacitor/*` (AD-1). Flavour-specific bundle ids are ticket 5. The appId prefix `app.numception` is a placeholder until store ids are registered (epic-native-apps).

</intent-contract>

## Implementation Notes

Oneshot: the hand-written change is small (config, scripts, typecheck include). The `ios/` and `android/` trees are generated by `cap add` and kept as generated.

- Installed `@capacitor/core`, `ios`, `android` ~8.5.3 as `apps/client` dependencies and `@capacitor/cli` ~8.5.3 as a devDependency. No package under `packages/` imports Capacitor.
- `apps/client/capacitor.config.ts`: appId `app.numception.dev`, appName `Numception`, webDir `dist`. Added to `tsconfig.node.json`'s include so `tsc -b` checks it.
- `cap:sync` script = `BASE_PATH= vite build && cap sync`. Clearing `BASE_PATH` means native always ships base `/`, even when the shell has the Pages `BASE_PATH` exported. Checked: with `BASE_PATH=/numception/`, both platforms' `public/index.html` still reference `/assets/`.
- iOS uses Capacitor 8's default Swift Package Manager setup (`ios/App/CapApp-SPM`), with no CocoaPods. The generated `.gitignore` files keep the copied `public/` web assets and the generated config out of git.
- Surprise: on the simulator the tracer text sat under the status bar, because the WKWebView content extends under it. Fixed in `apps/client/index.html` with `viewport-fit=cover` and safe-area-inset body padding, so the text is readable on a notched iPhone 13.
- Android: the project is generated and synced, but this machine has no Android SDK (and the JDK is 26), so no Gradle build was attempted.
