- (decision) Paradigm: hexagonal (ports & adapters) with functional core / imperative shell. core = pure deterministic TS domain; shell = app orchestration; adapters = renderer, DOM UI, platform (storage, audio, haptics, share, game services, telemetry). Prevents game rules leaking into renderer/UI and lets the renderer be swapped after the prototype
- (decision) Monorepo packages: core (pure, zero runtime deps beyond PRNG/schema), app (shell: store, scheduler, ports), render (renderer adapter), ui (DOM overlay), platform-web, platform-native (Capacitor), apps/client (composition root + Capacitor project). Dependency direction strictly inward toward core
- (decision) State mutation: single GameState per profile, changed only by core reducer step(state, command) -> {state, events}. Commands carry time (no clock reads in core). Renderer/UI never mutate state; they render state and animate domain events. Prevents dual sources of truth (e.g. renderer holding solved-ness)
- (decision) Determinism: core never calls Math.random/Date.now/performance.now; randomness only from a seeded PRNG passed in; integer/rational arithmetic only (no floats) in generator and puzzle values. Same inputs => identical puzzles on every platform (FR-5/FR-6/FR-32)
- (decision) Puzzle identity: puzzle = generate(seed, treePath, difficultySpec, generatorVersion, tuningVersion). treePath is canonical string. Generator plans a round top-down (top puzzle first, answers become lower-tier c values)
- (decision) Numbers: puzzle values are exact Rational {n,d} (d=1 for integers) in core from day one so FR-48 fractions/negatives need no data migration; display formatting is adapter concern
- (decision) Persistence: per-profile snapshot (versioned JSON) written after every command batch + append-only telemetry event log; writes atomic via Storage port; forward-only migrations in core keyed by saveFormatVersion. Storage is a port; adapters per platform
- (decision) Tuning configuration: single versioned JSON document validated by schema in core at load; all difficulty/scoring/pacing params read from it; core functions take config explicitly (no global). v1 may fetch newer config as data
- (decision) Ratings: rating module stores full response log entries (bucketId, playerOperatorKey, correct, responseMs, priorP, selection context, versions) so ratings are recomputable offline and mitigation for adaptive-selection noise can be added later without migration
- (decision) Telemetry: one versioned PuzzleEvent/AppEvent schema defined in core; events appended locally; POC export via dev-only path; v1 uploader adapter batches to first-party endpoint. Telemetry never blocks play
- (decision) Rendering split: canvas renderer owns play view only (shapes, transitions, zoom, particles); DOM overlay (ui package) owns control surface, stats, guide text, parent gate, and the parallel accessible tree. Accessible tree derived from core state, not from renderer scene graph
- (decision) Renderer adapter contract: RenderPort { mount, render(viewModel), play(domainEvents), setMotion, setTheme, destroy }. Prototype picks Phaser 4 or PixiJS v8 behind it; game logic unaffected by the choice
- (decision) Themes/transitions as data: theme = token set conforming to UX role grammar (JSON); transitions registered by id with calm/intense + start-mode tags; renderer resolves tokens, no hard-coded colours
- (decision) Profiles: profileId partitions all persisted data (state, ratings, stats, events). Active profile id + PIN hash stored in device-level settings record. Parent gate is a ui+app concern; core knows profile kind (kid/grown-up) for rule variants
- (decision) Daily Seed computed locally: seed = hash(UTC date + dailySeedSalt) with fixed generatorVersion per day; no server needed for v1 Daily Seed
- (decision) Platform capabilities (haptics, audio, share, game services, storage, telemetry transport, app lifecycle) are ports with web and native adapters chosen at composition root; feature code never imports Capacitor directly
- (decision) Testing: core gets unit + property tests (uniqueness over N generated puzzles, determinism snapshot across seeds); golden-seed fixtures pin generator output per generatorVersion; any change to output requires bumping generatorVersion
- (decision) Environments: dev (local Vite), playtest (static web build with dev panel: tuning switcher + event export), prod. Build flavour chosen at composition root via env flag; dev tooling tree-shaken out of prod
